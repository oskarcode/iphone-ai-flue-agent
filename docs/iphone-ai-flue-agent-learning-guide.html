1. Start Here

This is a small public Cloudflare Worker demo. Hono handles HTTP, Jev chooses one route, and a SQLite-backed Flue Durable Object conversation runs GLM-5.2 with optional retrieval tools.

13. Frontend to Backend

renderChatPage() returns all HTML, CSS, and JavaScript from the Worker. There is no React project, asset pipeline, or browser package dependency.

sendMessage()→fetch /chat/stream→consumeEvents()→handleChatEvent()→render()

Model output is rendered with textContent and constructed DOM nodes. The limited Markdown parser never assigns model text to innerHTML.

14. Backend and State

One-shot stateA random conversation ID is generated for every Shortcut request.
Browser stateThe browser retains one random ID, so follow-up turns reach the same Flue conversation.
Handoff stateKV stores only the initial selected text with a 600-second TTL.
Retry policyFlue is configured for up to four attempts and a three-minute timeout.

Jev failures fall back locally to a direct answer. Tool failures remain visible to the model; the prompt forbids claiming retrieval succeeded when it did not.

17. Code Walkthrough

  1. Bootstrap: src/app.ts reads Worker bindings and configures Flue's Workers AI provider once per isolate.
  2. Ingress: Hono validates text or chat history before any billable work.
  3. Routing: classifyWithJev() sends declarative route criteria through the AI binding and gateway.
  4. Orchestration: IphoneAssistant() attaches the route signal, model, tools, and metadata hooks.
  5. State: Flue owns durable conversation state; KV owns only temporary handoff text.
  6. Integrations: One research tool can return bounded Browser Run Markdown and up to five normalized search results.
  7. Output: one-shot routes await a complete answer; streaming chat sanitizes and forwards incremental events.
  8. Errors: structured console.error(JSON.stringify(...)) records dependency failures without returning internals to clients.

Explain-back quiz

Why are both TypeScript types and runtime validation present?
Types protect the developer at build time; public JSON and model tool calls are still unknown at runtime and must be checked.
What is the difference between KV and the Flue Durable Object here?
KV transfers one short-lived handoff payload. The Durable Object owns durable per-conversation agent execution/state.
Where would you look if private reasoning appeared in the UI?
projectConversationChunk(), its tests, and the /chat/stream projection call site.
Why is src/chat-page.ts not React?
The UI is intentionally small and is returned as one HTML string by the Worker, avoiding a second frontend build and dependency tree.
