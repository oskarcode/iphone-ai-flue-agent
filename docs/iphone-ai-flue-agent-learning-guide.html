Safe Change Checklist

Before editing and deploying

  1. Identify the route and browser/Shortcut caller.
  2. Preserve Access and bounded-input checks.
  3. Keep GitHub requests on fixed hosts and immutable commit SHAs.
  4. Keep ready metadata and guide content in one atomic KV record.
  5. Never edit an applied Durable Object migration tag; add a new migration.
  6. Update tests and this guide when interfaces or state change.
  7. Run npm run check.
  8. After deploy, test health plus one real protected flow and inspect logs.

Code Walkthrough

Read files in runtime order

src/app.ts

Worker bootstrap and Hono route registry. It configures the Flue AI provider, validates bodies/history, classifies requests, dispatches agents, projects SSE, and coordinates KV/DO cleanup. Start with createGithubLearningSession(), then the /learn/:id routes.

src/agents/iphone-assistant.ts

Normal durable assistant. Flue hooks configure the model, route-aware prompt behavior, web-research tool, retries, and conversation lifecycle.

src/agents/github-learning.ts

Temporary repository tutor. Initial data fixes one repository/commit. Persistent guide-published prevents early completion; the Cloudflare extension schedules cleanup.

src/tools/github-repository.ts

Trust boundary for GitHub. Resolves public metadata/tree, filters readable paths, fetches bounded raw text, validates the guide schema, and rejects repeated publication.

src/lib/learning-session.ts

KV lifecycle. One atomic record contains metadata plus guide; a separate receipt key prevents concurrent status overwrites.

src/learning-page.ts

Fixed mobile-first HTML/CSS/JS renderer. Escapes model values, watches queued work by SSE/polling, captures bounded guide selections outside the tutor panel, renders text-only follow-ups, and deletes sessions.

src/chat-page.ts

Self-contained general chat UI. Sends bounded history and consumes projected SSE without placing raw model HTML in the DOM.

src/tools/jev-router.ts

Defines the four-route choice contract and parses Jev's nested result. The github_learning choice takes priority whenever the current request contains a github.com/owner/repository URL, including the existing handoff prompt that asks to explain copied text.

src/tools/web-research.ts

Validates public URLs, reads pages through Browser Run, searches public providers, and bounds returned evidence.

src/lib/chat-events.ts

Converts internal Flue chunks into the small public browser event vocabulary.

src/lib/configured-message.ts

Encodes trusted routing/caller metadata separately from user-visible model text.

src/lib/gateway-metadata.ts

Transforms verified Access identity into pseudonymous AI Gateway metadata.

src/lib/grammar-correction.ts

Builds deterministic grammar input and rejects empty, truncated, or filtered output.

src/prompts.ts

Application-owned model instructions for the main assistant and grammar path.

flue.config.ts, vite.config.ts, vitest.config.ts, wrangler.jsonc

Build target, plugins, Node test environment, production resources, bindings, migrations, and observability.

test/*.test.ts

Pure parser, route, renderer, event-projection, security, and learning-state tests. github-learning.test.ts proves safe generated JavaScript; learning-chat-route.test.ts proves selected context is bounded and labeled untrusted before durable dispatch.

Labs and Quiz

Practice safe maintenance

  1. Trace POST /chat/api with a GitHub URL through every called symbol.
  2. Add a unit test for a new skipped repository artifact without changing fetch logic.
  3. Use the Blueprint diagram to explain why the submission receipt is separate from the guide record.
  4. Run the local Learning Agent and ask: "Which code prevents raw repository text from becoming instructions?"
Why is a commit SHA stored?

It makes every later raw-file read immutable so follow-up answers use the same evidence.

Why not store ready metadata before the guide?

The browser could observe ready without content. One record publishes both atomically.

What is the Django equivalent of src/app.ts?

It combines URL registration, view functions, middleware, and service orchestration.
