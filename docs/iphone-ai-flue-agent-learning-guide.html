Project From 10,000 Feet

This Worker gives iPhone Shortcuts and a browser chat one assistant endpoint for pasted text, questions, URLs, and current-information research.

Purpose, users, inputs, and outputs

Trace a requestFollow an iPhone or browser turn from Hono validation to Jev, Flue, GLM, and JSON/SSE output.
Understand stateSeparate ten-minute KV handoff data from durable per-conversation Flue state.
Change behavior safelyKnow which prompt, route, tool, UI, and binding files move together.
Debug from evidenceUse tests, Worker logs/traces, AI Gateway, Browser Run, and browser network events.

Essential vocabulary

TermBeginner meaningFirst source landmark
JevA structured classifier that chooses one route before answer generation.src/tools/jev-router.ts
FlueThe durable agent runtime that dispatches turns, calls the model/tools, and emits events.src/agents/iphone-assistant.ts
BindingA Cloudflare-provided service object exposed to Worker code without embedding credentials in source.wrangler.jsonc

The system story

Shortcut/browser→Hono Worker→direct grammar or Jev + Flue→GLM + optional tools→JSON or SSE

Purpose and users

The primary user is an iPhone owner who wants separate Shortcuts for fast clipboard grammar correction and for a routed assistant handling pasted-text explanation, direct questions, current information, URL reading, and browser follow-up chat. API clients can also use the JSON routes directly.

Capabilities and boundaries

Technology stack

Cloudflare Workers hosts Hono, Flue, Workers AI, AI Gateway, Browser Run, Workers KV, and a SQLite-backed Durable Object. TypeScript is bundled by Vite using the Cloudflare and Flue plugins. Evidence: package.json, vite.config.ts, and wrangler.jsonc.

Security posture: Cloudflare Access protects API and chat routes, using service tokens for Shortcuts and interactive identity for browser chat. /health remains public and application-level rate limiting is not configured.

Core concept: route before generation

What it is. Jev chooses direct_answer, web_research, or clarification before GLM writes the response. This separates route policy from answer generation so the model receives one explicit execution instruction.

How it works here. classifyWithJev() sends the prompt and optional recent conversation to AI.run(). The route becomes a Flue signal that the model must follow.

const result = await ai.run(JEV_MODEL, { state, questions: QUESTIONS }, gatewayOptions);
return parseJevRoute(result);

Common mistake. Adding a route only to the Jev criteria leaves the route union, prompts, UI labels, tests, and metadata inconsistent. Change all of them together and run npm run check.

Core concept: durable Flue conversation

What it is. A conversation ID addresses one SQLite-backed Durable Object agent. One-shot calls create a new UUID; browser turns reuse one UUID so prior context remains available.

Where it lives. src/app.ts: runAgent(), src/agents/iphone-assistant.ts: IphoneAssistant, and wrangler.jsonc: migrations.

Core concept: retrieval is evidence, not instructions

The web_research tool may return Browser Run Markdown and public search results. The tool output includes an explicit untrusted-evidence notice, and the prompt forbids inventing reads or searches. Keep this boundary when changing prompts or providers.

Core concept: sanitized streaming

Flue emits rich runtime events, but projectConversationChunk() exposes only classification, token, generic planning, tool lifecycle, and response lifecycle events. Raw reasoning and tool payloads stay private. The tests in test/chat-events.test.ts protect this contract.

Docs / Understand / Architecture

Architecture

One Worker owns ingress and the browser UI. Durable Flue conversations, temporary KV handoffs, Workers AI, and Browser Run sit behind Cloudflare bindings.

System context

iPhone Shortcut / browser / API→Hono Worker→direct grammar or Jev + Flue agent→GLM and optional web evidence→JSON / HTML / SSE

Cloudflare Access authenticates API and chat requests before they reach the Worker. Shortcuts use a service token, browser chat uses an interactive Access session, and /health remains public. Worker-to-service identity comes from account bindings. The browser chat is synchronous HTTP plus one streaming response; there are no queues, scheduled jobs, webhooks, Workflows, or WebSockets.

Deployable units and topology

UnitEntrypoint/lifecycleDependenciesEvidence
Workersrc/app.ts default Hono appAI, Browser, KV, generated Flue DOwrangler.jsonc

Why it is shaped this way

One Worker keeps the demo small. Grammar correction stays stateless because it is a finite transformation with one fixed prompt. Jev makes assistant tool policy explicit before generation. Durable conversation IDs preserve follow-up context. KV keeps copied text out of the handoff URL. The event projector prevents the convenient live UI from becoming a private-runtime-data leak.

Docs / Understand / End-to-end flows

End-to-End Flows

Start with the user action, follow every request in order, and finish at the result the user sees. Every discovered endpoint is reconciled at the end.

Big picture

  1. One-shot Shortcut: selected or typed text becomes one JSON answer.
  2. Grammar Shortcut: clipboard or shared text becomes one corrected string without routing or conversation state.
  3. Shortcut handoff: selected text moves through temporary KV into an automatically started browser conversation.
  4. Manual browser chat: the user opens the chat page and streams follow-up turns under one conversation ID.
  5. Non-streaming chat API: an external client reuses a conversation ID and receives one complete JSON response.
User action→client request→src/app.ts route→direct AI or Jev + Flue→optional research→JSON / HTML / SSE→visible result

Flow 2: clipboard grammar correction

This endpoint preserves the original grammar Shortcut contract while deliberately bypassing the agent system. The fixed prompt asks for spelling and grammar corrections without changing tone or structure.

1User runs the grammar Shortcut with Clipboard or Share Sheet text.POST /v1/correctExternal iPhone Shortcut; setup in docs/SHORTCUT_GUIDE.mdsrc/app.ts: POST /v1/correct → readTextBody(c,true) → createGrammarRequest()None: no KV write, conversation ID, or durable state.AI.run('@cf/zai-org/glm-5.2') through AI Gateway; no Jev, Flue, chat, or tools.200 {corrected_text}; 400 invalid text; 502 model or response-shape failure.Shortcut copies, replaces, or displays corrected_text.

Contract: input is non-whitespace text up to 30,000 JavaScript UTF-16 code units in a JSON body capped at 200,000 bytes. Application code passes input and returns provider output without trimming boundary whitespace, although the model may still normalize it. The request sets temperature to zero, disables reasoning, allows up to 32,768 completion tokens, and rejects any explicit finish reason other than stop. Unit tests cover request construction, response parsing, the real Hono route, validation boundaries, body limits, gateway options, and failure mapping; the Access-authenticated Shortcut was also verified against the live endpoint.

Gateway identity chain: the route reads verified Access identity and passes gatewayMetadata('grammar-correction', gatewayCaller) directly to AI.run(). A post-deploy Shortcut request confirmed the service-token fields in AI Gateway logs.

Research subflow used by answer flows

Search uses a 10-second timeout, DuckDuckGo first, and Wikipedia after any DuckDuckGo failure. Page and search branches can partially succeed; the tool throws only when every requested evidence path fails. Example: handoff key lifecycle

await CHAT_SESSIONS.put(`chat-session:${sessionId}`, text, { expirationTtl: 600 });
const text = await CHAT_SESSIONS.get(key);
await CHAT_SESSIONS.delete(key);

The write keeps selected text out of the URL. The later read/delete is easy to understand but is only best-effort one-time use. Do not claim strict single consumption without moving this state to an atomic storage design.

Input and abuse controls

Cloudflare Access authenticates API and chat ingress. The Worker reads verified identity through ctx.access and adds pseudonymous access_user_id metadata to AI Gateway calls for human sessions; Shortcut calls use service_token_id with caller_type=service_token. The built-in cf.user_id is unavailable on this path because env.AI.run() is a new internal binding request that selects a gateway by ID; it does not send the original request or Access JWT through an AI Gateway custom hostname. AI Gateway adds cf.user_id only when a human request with an Access user subject reaches the Access-protected gateway hostname directly, and service tokens never receive that human field. Email and reserved cf.* fields are not supplied by this application. Text, history count/length, conversation IDs, model tool arguments, URL schemes/ports/credentials, literal private IPs, response bytes, Markdown length, result count, and network timeouts are also bounded. These controls do not replace DNS-aware SSRF defenses, quotas, or atomic handoff consumption.

Production hardening: add rate limits, DNS/redirect validation, and a deliberate conversation-retention policy before broader exposure.

package.json config

Runtime position: before local execution or deployment. Why it exists: pins dependencies and names repeatable commands. Entry: an npm command. Main code: check sequences typecheck, tests, and build; deploy runs that gate before Wrangler. Exit: exact config depends on the selected script. JSON has no functions or comments, and script order is runtime behavior: replacing && would allow later steps after failure. The latest executed npm run check passed typecheck, all test files, and build.

tsconfig.json config

Main code: strict settings check source while noEmit leaves JavaScript generation to Vite. Exit: diagnostics return to the npm script. Type annotations and unions help before deployment but disappear from emitted JavaScript, so routes still perform runtime validation.

async function runAgent(prompt: string, conversationId = crypto.randomUUID(), routingContext?: string, gatewayCaller?: GatewayCallerMetadata) {
  const agent = init(IphoneAssistant, { id: conversationId });
  const receipt = await agent.dispatch(encodeConfiguredMessage(prompt, routingContext, undefined, gatewayCaller));
  const reply = await agent.read(receipt);
  return { text: reply.text, route: routeFromReplyData(reply.data) };
}

Execution: gatewayCallerForRequest() reads verified c.executionCtx.access identity and returns pseudonymous caller metadata; failures omit observability metadata without weakening Access authentication. identityAwareBinding.run() recovers the current caller from Flue's private envelope and merges it into existing assistant Gateway metadata. readTextBody() narrows untrusted JSON; validateChatMessages() checks history; runAgent() dispatches one durable turn; createChatSession() writes expiring KV state. Grammar attaches identity directly, while assistant/Jev calls propagate it through the configured envelope.

How execution leaves: grammar calls createGrammarRequest(), AI.run(), and correctedTextFromAi(); one-shot/chat API calls encodeConfiguredMessage(); streaming calls classifyWithJev(), then the encoder and agent, then projectConversationChunk(); GET /chat calls renderChatPage(); handoff routes call KV. Beginner TypeScript: Hono<AppEnv> supplies compile-time context typing; unknown forces runtime checks; Promise<T> means callers must await asynchronous completion; routingContext? is optional; default parameters run only when the argument is undefined. First failure signals are HTTP status, structured console.error, Worker trace, and AI Gateway request.
